### Experimental Rust core

This library provides scanning, analysis, resolution, cache, media and tool-discovery modules. Resolution is exported but still lacks a Rust CLI/TUI integration and remains under hardening. No Rust CLI or TUI exists yet. Run `cargo test --manifest-path rust/Cargo.toml` from the repository root.

### Integration status

`rust/` is an independent Cargo library, not a Python extension or subprocess used by the application. The installed `deconflict` entry point, CLI, TUI, scanning and resolution still run the Python code; the Python wheel does not include or build this crate. Rust code currently runs only when invoked explicitly, for example through Cargo tests or the benchmark in `benchmarks/README.md`. The executable contract tests currently exercise Python, not Rust. No migration or switching of existing users is required.

`ScanConfig` accepts the Python `[scan]` fields plus `workers` (default 2), `max_in_flight` (default 64), and `follow_symlinks` (default false). Callers can override these fields before scanning; both numeric limits must be positive. Discovery and file analysis share workers. Analysis is favored over directory iteration, which yields between entries; unopened directories can wait for an open iterator to finish. Active jobs, job and event channels, and open directory handles are bounded. Pending directory and analysis tasks, visited sets, and final groups are held in memory without a fixed limit; memory use grows with the workload. Directories are not rescanned to limit queue size. Worker event sends may block, but workers never enqueue jobs. Cancellation stops scheduling and drains running jobs, but does not interrupt an active directory read or hash. Callbacks must not block indefinitely; a panic shuts down workers and is propagated.

Events are provisional individual conflict-file hashes, not group analysis and never authorization for mutation. Returned groups are sorted and complete only when not cancelled and without errors. A group contains the expected base path, even if it is missing; provisional analysis does not hash bases. The separate group analysis APIs compare base and copy hashes and text detection, with optional copy stamps and recommendation diagnostics. Callers must supply the group kind; the experimental media module is not integrated into analysis and does not yet have full parity. Recommendations are not authorization for mutation. Provisional errors appear in the result. Analysis checks size and modification time on the open handle and current path, and on Unix checks change time and path device and inode; these checks cannot detect all races and are not an atomic snapshot.

Directories are canonicalized and deduplicated, including overlapping roots and symlink loops; output uses canonical directory paths, unlike the Python reference. Symlinks within roots are ignored by default; enabling them follows both directory and file links, potentially outside roots. A symlink supplied as a root is followed even when disabled. Non-UTF-8 names are reported as errors. Windows case folding has not been tested on Windows and may differ across Unicode versions. Filesystem snapshots are not atomic; permission errors and missing files are reported, not silently discarded.

Custom patterns use `fancy-regex`, not Python `re`: named captures and backreferences, lookaround and a leading `(?i)` flag work, but full Python regex syntax and matching semantics are not guaranteed. Leading `(?a)` supports a limited subset; character classes, case-insensitivity, scoped flags and word boundaries are rejected. Unsupported expressions fail when patterns are built; matching can also fail at runtime due to the regex backtracking limit. See `benchmarks/README.md` for a comparison of differing workloads. Linux processes inherit scheduling and I/O priorities; users can launch their application with `nice`/`ionice` where available, with no cross-platform priority guarantee. Resource controls do not guarantee low CPU, memory, or I/O usage.
